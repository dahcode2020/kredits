# KREDIT — Internationalisation (i18n) Complète

> 4 langues FR/EN/NL/DE — EUR — détection hiérarchique — persistance — tout externalisé — formats locaux — fr-BE distinguable — templates multilingues.

---

## 1. Principes

- **Aucun texte utilisateur en dur dans un composant React.** Toute chaîne passe par `t(locale, namespace:key)` ou `<Trans>`. Lint `no-restricted-syntax` bloque les littéraux.
- **Source de vérité :** `frontend/i18n/{fr,en,nl,de}/*.json` + `backend/src/i18n/locales/{fr,en,nl,de}/*.json` (sync via `packages/shared` en prod).
- **ICU MessageFormat** pour pluriels, genres, sélecteurs, interpolations (`{amount, number}`, `{date, date}`, `{count, plural, one{# dossier} other{# dossiers}}`).
- **Clés hiérarchiques** `namespace:key` : `credit:simulator.title`, `admin:decision.approve`, `errors:CREDIT_AMOUNT_EXCEEDS_CEILING`.
- **Fallback** : `fr` par défaut (Belgique). Chaîne manquante → clé → log Sentry `i18n.missing`.
- **Versionnage** : chaque fichier JSON versionné, `needs_legal_validation` pour mentions légales.

## 3. Détection & persistance (hiérarchie stricte)

**Ordre :**

1. **Préférence utilisateur** (si authentifié) → `users.locale` (DB) + `customer_preferences.locale` + cookie `NEXT_LOCALE` + `localStorage:kredit-locale`. Priorité la plus haute. Modifiable dans `/[locale]/settings` et `/[locale]/profile`. Persistance DB + cookie `SameSite=Lax, maxAge 1y, Secure`.
2. **Préférence navigateur** → `Accept-Language` header (middleware) → `navigator.languages` (client). Parse qualité `q`: `fr-BE,fr;q=0.9,en;q=0.8` → première locale supportée.
3. **Langue par défaut** → `fr` (`fr-BE`). Jamais `en` par défaut en BE.

Détection centralisée dans **`frontend/lib/locale-detection.ts`** (locales supportées, défaut,
`parseAcceptLanguage`, hiérarchie cookie → navigateur → `Accept-Language` → défaut, attributs du
cookie `NEXT_LOCALE`). `middleware.ts`, `lib/i18n.ts` et `hooks/useLocale.ts` consomment ce module:
aucune copie locale, sinon le serveur et le client peuvent retenir deux langues différentes et
l'hydratation échoue (voir `docs/hydration.md`).

**Flux middleware (`frontend/middleware.ts`) :**

```
request → a déjà /{locale}/… ? → oui → set cookie NEXT_LOCALE si pref user
        → non → lire cookie NEXT_LOCALE → si présent et supporté → redirect /{cookie}/path
        → sinon → lire JWT locale (si auth) → redirect
        → sinon → parser Accept-Language → redirect /{best}/path
        → sinon → redirect /fr/path
```

**Persistance :**

- Écriture : `useLocale().setLocale('nl')` → `localStorage.setItem('kredit-locale','nl')` → `document.cookie='NEXT_LOCALE=nl; path=/; max-age=31536000'` → `PATCH /api/v1/customers/me {locale:'nl'}` si auth.
- Lecture serveur : `cookies().get('NEXT_LOCALE')` → `headers().get('accept-language')` → `user.locale` (décodé du JWT).
- SSR : `layout.tsx` génère `<html lang={locale}>` + `<link rel="alternate" hreflang="fr" href="/fr/…">` pour SEO.

**Changement de langue :** `LanguageSwitcher` (Header + Footer) `→` `router.push('/nl' + pathnameWithoutLocale)` + persistance ci-dessus. Pas de reload complet, pas de perte d'état.

## 6. Formats locaux (Intl)

Centralisés dans `frontend/lib/formatters.ts` + `backend/src/i18n/formatters.ts` (même logique, pas de divergence).

| Type | API | Exemple `fr-BE` vs `en-BE` vs `nl-BE` vs `de-BE` |
|------|-----|----------------------------------------------------|
| **Date** | `formatDate(value, locale)` (`Intl.DateTimeFormat` + `timeZone: Europe/Brussels`, valeur d'abord passée par `resolveDate`) | `09/09/2026` (fr-BE) vs `09/09/2026` (en-BE) vs `09-09-2026` (nl-BE) vs `09.09.2026` (de-BE) |
| **Heure** | `timeStyle:'short'` | `14:22` vs `2:22 PM` (en) |
| **DateTime** | `formatDateTime(date, locale)` | `09/09/2026 à 14:22` |
| **Nombre** | `Intl.NumberFormat(locale)` | `1 234,56` vs `1,234.56` vs `1.234,56` |
| **Monnaie** | `Intl.NumberFormat(locale,{style:'currency',currency:'EUR'})` | `15 000,00 €` (fr-BE) vs `€15,000.00` (en) vs `€ 15.000,00` (nl-BE) vs `15.000,00 €` (de-BE) |
| **Pourcentage** | `percent 38.4%` → `Intl.NumberFormat(locale,{style:'percent', maximumFractionDigits:1})` | `38,4 %` (fr-BE, espace insécable) vs `38.4%` (en) |
| **Adresse** | `formatAddress({street, number, box, postal, city, country}, locale)` | `Rue de la Loi 100 bte 5, 1000 Bruxelles, Belgique` (fr) vs `Wetstraat 100 bus 5, 1000 Brussel, België` (nl) |
| **Téléphone** | `libphonenumber-js` `parsePhoneNumber(num, 'BE').formatInternational()` | `+32 470 12 34 56` (toutes locales, indicatif BE), validation `isValidNumber` |

**Implémentation :**

```ts
// lib/formatters.ts
export const localeMap = { fr:'fr-BE', en:'en-BE', nl:'nl-BE', de:'de-BE' } as const;
export const formatDate = (d: Date, locale: Locale) => new Intl.DateTimeFormat(localeMap[locale], { day:'2-digit', month:'2-digit', year:'numeric' }).format(d);
export const formatCurrency = (n: number, locale: Locale) => new Intl.NumberFormat(localeMap[locale], { style:'currency', currency:'EUR' }).format(n);
export const formatPercent = (n: number, locale: Locale) => new Intl.NumberFormat(localeMap[locale], { style:'percent', minimumFractionDigits:1 }).format(n);
export const formatPhoneBE = (num: string) => parsePhoneNumber(num, 'BE').formatInternational();
export const formatAddressBE = (a: Address, locale: Locale) => { /* BE: street number box, postal city */ }
```

Tous les composants utilisent **uniquement** ces helpers, jamais `toLocaleString` direct.

## 7. Différences linguistiques & régionales

- **Pluriels ICU** : `fr`/`nl`/`de` ont 2 formes, `en` 2. Ex: `credit.documents.count: "{count, plural, one {# document} other {# documents}}"`
- **Listes** : `Intl.ListFormat(locale, {type:'conjunction'})` → `A, B et C` (fr) vs `A, B and C` (en) vs `A, B en C` (nl) vs `A, B und C` (de)
- **Genres** : éviter accords si possible, ou clés séparées `credit.applicant.male`/`female` + `select`
- **Formalité** : FR/NL/DE utilisent `vous/u/Sie` (vouvoiement) pour crédit, EN `you`. Jamais `tu/je`.
- **Dates relatives** : `Intl.RelativeTimeFormat` → `il y a 2 jours` vs `2 days ago` vs `2 dagen geleden` vs `vor 2 Tagen`.
  Dans un composant, passer par `<RelativeTime date locale now />` (`components/ui/RelativeTime.tsx`) :
  le premier rendu est déterministe (absolu, ou relatif depuis le `now` fourni par le serveur) et la
  bascule en relatif se fait après hydratation — `formatRelative()` lit l'horloge à l'appel, il est
  réservé aux logs/exports (le garde-fou `relative-time-in-render` l'interdit dans `app/` et `components/`).
- **Tri** : `Intl.Collator(locale)` pour listes clients
- **Fuseaux** : `Europe/Brussels` fixe, stockage UTC, affichage locale.

## 8. Usage dans le code (zéro texte en dur)

**Frontend (App Router) :**

```tsx
// ❌ INTERDIT
<button>Approuver</button>

// ✅ OK
import { useTranslation } from '@/lib/i18n';
const { t } = useTranslation('admin');
<button>{t('decision.approve')}</button>
```

**Hook :**

```ts
// lib/i18n.ts
export function useTranslation(ns: Namespace) {
  const locale = useLocale(); // 1) user 2) browser 3) fr
  return { t: (key: string, vars?: any) => tRaw(locale, `${ns}:${key}`, vars), locale };
}
```

**Serveur :**

```ts
// app/[locale]/dashboard/page.tsx
import { getTranslations } from '@/lib/i18n/server';
export default async function Page({ params:{locale} }) {
  const t = await getTranslations(locale, 'dashboard');
  return <h1>{t('greeting', { name })}</h1>
}
```

**Backend :**

```ts
// notifications.service.ts
const locale = customer.locale ?? 'fr';
const tpl = await this.templates.findOne({ event:'APPLICATION_APPROVED', channel:'EMAIL', locale });
const subject = this.i18n.t(locale, `notifications:event.APPLICATION_APPROVED.subject`, { id });
```

**Lint :** `eslint-plugin-i18n` → `no-literal-string` sauf `className`, `aria-*` constants.

## 9. Templates WhatsApp / Email / SMS multilingues

- Stockés en DB `notification_templates` + fichiers `backend/src/i18n/templates/{whatsapp,email,sms}/{fr,en,nl,de}/`
- Clé : `event + channel + locale` unique.
- WhatsApp : `HSM` approuvé Meta, `waba_id`, `template_name`, `language` (`fr`, `en_US`, `nl`, `de`), variables `{{1}}`.
- Email : MJML → HTML inline, `subject` + `html` + `text` par locale, `from` localisé.
- SMS : 160c, pas d'accent si possible pour GSM-7, variables courtes.
- Admin peut éditer **EMAIL/SMS/PUSH** en direct, **WhatsApp** nécessite resoumission Meta (brouillon + validation).

## 9quater. Copie des coquilles (nav, accès, bandeaux) — budget décroissant

`components/customer/CustomerShell.tsx` et `components/admin/AdminShell.tsx` enveloppent **toutes** les
pages métier : leur navigation et leurs écrans d'accès étaient écrits en dur en français, donc un
utilisateur `nl`/`de` avait une page traduite dans un menu français. Les deux coquilles n'ont plus
aucune chaîne en dur :

- la table de navigation porte des **clés** (`{ href, labelKey, icon }`) et le rendu fait
  `tr(item.labelKey)` — pas de `t()` au niveau module: la table est évaluée une fois, la locale
  n'existe qu'au render ;
- `const tr = (key, vars) => t(locale, \`common:${key}\`, vars)` dans le composant : déterministe
  (la locale vient du segment `[locale]`), donc aucun risque d'hydratation — les coquilles rendent de
  toute façon un skeleton tant que le store `persist` n'a pas parlé ;
- les phrases qui portaient du balisage (`<code>kredit-auth</code>`, `<strong>{role}</strong>`) sont
  passées en variables ICU (`{key}`, `{role}`, `{connected}`, `{required}`) : une chaîne par langue
  plutôt qu'un puzzle de fragments, sinon la grammaire des unes casse chez les autres ;
- le compteur d'alertes utilise le pluriel ICU (`{count, plural, one {…} other {…}}`), résolu par
  `localeToIntl[locale]`, pas par celui du runtime.

**Le reste de l'app n'est pas traduit** (184 lignes réparties dans 35 fichiers, dont 51 pour la
page d'accueil): l'interdire d'un coup produirait un commit relou à relire. `scripts/check-copy.mjs`
(`npm run check:copy`, intégré à `npm run check` et au job `gardes` de `.github/workflows/ci.yml`) tient donc
un **budget par fichier**: `components/customer/**` et `components/admin/**` sont à zéro (règle dure),
tout le reste a son compteur figé dans `scripts/copy.baseline.json` et **ne peut pas augmenter**. Après
une traduction: `npm run check:copy:update` pour redescendre la barre, et le script signale les fichiers
passés à zéro à retirer du budget. Limites assumées: l'heuristique regarde les accents, donc une ligne
déjà multilingue dans le JSX (`Offline is beperkt…` sur `app/[locale]/offline/page.tsx`) est comptée
aussi — le budget l'absorbe, ce n'est pas une erreur à corriger en urgence.

## 9quinquies. Page d'accueil : zéro copie en dur (et pourquoi c'est le pire endroit)

`app/[locale]/page.tsx` portait le plus gros bloc de copie française de l'app (51 lignes comptées par
`check-copy`). Il est descendu à **zéro** : hero, carte simulateur, bandeau partenaires, checklist
`about`, carte `compliance`, les 4 fiches produits, les 4 étapes du process (onglets), les 6 services,
la section simulateur, les 3 témoignages, les 3 rôles, la note d'audit, la FAQ (4 questions), tout le
formulaire de contact et le bandeau final passent par `common:heroCard.*`, `products.*`, `process.*`,
`services.*`, `testimonials.*`, `roles.*`, `faq.*`, `contact.*`, `cta.simulate`.

C'est le fichier **le plus visible du site** et le seul de cette liste rendu côté serveur dans la langue
du segment : une chaîne qui y repasserait en dur atterrit littéralement dans le HTML de `/en`, `/nl` et
`/de` — donc dans l'index, les partages sociaux et un simple `curl`. D'où une **règle dure**
(`FLOOR_FILES` dans `scripts/check-copy.mjs`) plutôt qu'un budget : la page n'a pas le droit de
recommencer à dériver, son compteur ne se « retolère » pas. (Les autres pages restent en dur mais sont
rendues après hydratation : moins grave pour le SEO, d'où le budget décroissant plutôt que l'interdit.)

Le verrou croisé : `tests/unit/i18n-keys-usage.spec.ts` balaie `app/`, `components/`, `features/`,
`hooks/`, `lib/`, récupère toute chaîne à points (`tr("a.b")`, `labelKey: "a.b"`, `items: ["a.b"]`) et
exige que **toute clé qui se résout quelque part se résolve dans les quatre langues** — une clé ajoutée
pour `fr` seulement, c'était exactement le mode de défaillance silencieux de `t()` (fallback + simple
`console.warn`). Les exceptions légitimes (endonymes, toponymes) vivent dans une liste **partagée** par
les deux détecteurs : `tests/unit/translation-exceptions.ts`, sinon un test accepte ce que l'autre refuse.

Pour voir ce qui reste à traduire dans un fichier sans faire échouer le build :
`node scripts/check-copy.mjs --show 'app/[locale]/dashboard/page.tsx'`.

## 9sexies. Chrome PWA : les bannières n'ont pas droit au français en dur

`components/pwa/*` — pastille de connexion, bandeau hors ligne, invite d'installation, proposition de
mise à jour, gestionnaire de notifications push — est rendu par `app/[locale]/layout.tsx`, donc sur
**toutes** les pages, y compris les routes live-SDK et la page de repli servie par le service worker.
Sa copie était en dur en français : un investisseur `nl` en mode dégradé recevait l'avertissement
« Les données financières ne sont pas disponibles hors ligne par sécurité » dans une langue qu'il ne
parle pas, au moment précis où il est le moins joignable. Les 41 chaînes (`pwa.online`, `pwa.offlineDot`,
`pwa.install`, `pwa.installNote`, `pwa.updateApply`, `pwa.pushTitle`, `pwa.retry`, `pwa.operation`,
`pwa.offlinePageTitle`, …) vivent maintenant dans `common:pwa.*` des quatre dictionnaires, et
`components/pwa` est passé en **`FLOOR_DIRS`** (compteur à zéro, comme `components/customer` et
`components/admin`).

Deux choses au passage, trouvées en descendant dans ces fichiers :

1. **Le défaut de prop, angle mort du budget.** `function ServerRequiredNotice({ actionLabel = "Opération" })`
   et `function RetryButton({ label = "Réessayer" })` n'étaient **pas** comptés par l'heuristique de copie :
   elle exige deux mots, et un défaut d'un seul mot lui passe sous le nez. Or un défaut écrit dans la
   signature est pire qu'une chaîne dans le JSX — il s'affiche dès qu'un appelant omet la prop (c'est le
   cas de `/[locale]/offline`, qui fait `<RetryButton />`) — et on ne peut pas le corriger par dictionnaire.
   `check-copy.mjs` porte donc une **seconde règle, sans budget** : toute chaîne accentuée en position de
   défaut de paramètre fait échouer le contrôle, quel que soit le fichier. La forme correcte est une prop
   optionnelle résolue dans le corps : `{ label }: { label?: string }` puis `label ?? t("pwa.retry")`.
2. **Les deux dictionnaires.** `app/[locale]/offline/page.tsx` contenait son propre
   `const copy = { fr: …, en: …, nl: …, de: … }` à côté des dictionnaires officiels — plus huit chaînes
   françaises posées en dur autour (« Disponible hors ligne », « Simulateur local », « Accueil », « Besoin
   d'aide ? », « Contact ») et un repli `copy[locale] || copy.fr` qui servait du français à une locale
   inconnue. La page lit maintenant `t(locale, "pwa.offline*")` comme le reste du site et rejoint
   `FLOOR_FILES` : son texte est rendu **côté serveur**, donc lisible dans un `curl /nl/offline`.

Ce qui a été corrigé autour, révélé par ces contrôles : `lib/i18n.ts` ré-exporte `isSupportedLocale` (une
page qui valide `params.locale` avec son propre `|| "fr"` invente son fallback) ; `aria-label="Déconnexion"`
du header passe par `common:shell.logout` ; et `scripts/check-copy.mjs` ignore désormais les blocs
`/** … */` — la documentation du projet est en français et n'est jamais rendue, elle produisait un faux
positif sur chaque fichier correctement documenté, et un faux positif appris, c'est un contrôle désactivé.

Enfin, la stratégie « ne pas traduire » : `CACHE_STRATEGIES[*].description` (et `docs`, `clientSide`) reste
en français dans `lib/pwa.ts` et **doit** y rester. Ces descriptions avaient fuité dans une ligne de statut
du bandeau d'avertissement ; c'est de la documentation développeur, et `lib/pwa.ts` est importé par du code
**edge** (le middleware) — y faire entrer le i18n gonflerait le bundle de bord pour une chaîne que
l'utilisateur ne doit pas lire. L'interface n'affiche plus que l'identifiant de stratégie
(`Stratégies: FINANCIAL_DATA`), nom technique commun aux quatre langues.

Le même mouvement a attrapé le **skip-link** : `<a href="#main">Aller au contenu</a>` était rendu par
`app/layout.tsx`, le seul layout qui **ne peut pas** connaître la locale (`params === {}` en Next 14) — donc
français garanti sur les quatre marchés, dans le tout premier nœud focusable du document, lu avant l'en-tête
par un lecteur d'écran. Il vit maintenant dans `app/[locale]/layout.tsx` avec `common:shell.skipToContent`
(« Naar hoofdinhoud », « Zum Inhalt springen »).

Verrou : `tests/unit/pwa-chrome-i18n.spec.tsx` monte les composants en jsdom avec `next/navigation` simulé
et vérifie, pour chacun des quatre marchés, que le texte rendu **est** la valeur du dictionnaire de cette
locale — et qu'il ne contient pas la valeur française. Il rend aussi `/[locale]/offline` en
`renderToString` (le `RetryButton` client doit suivre le segment `[locale]` dès le premier rendu) et contrôle
statiquement que les sept fichiers du répertoire ne portent aucune chaîne française hors commentaires.

## 9septies. Axe « strict » et consoles d’administration

Le budget décroissant ne voyait que l’**accent**. Trois familles lui échappaient : un mot français sans
accent (« Produits », « Contact », « Score »), un fragment collé à un nombre (« 338,84€ / mois »), et une
chaîne fabriquée **hors JSX** — par le moteur de simulation (`score.explanation`, `warnings[].message`,
`requiredDocuments[].label`) ou par un tableau de configuration (`{ k: "Clients" }`,
`{ k:'admins', label:'Administrateurs' }`).

`scripts/check-copy.mjs` a donc un second axe, appliqué aux seuls fichiers sous règle dure
(`FLOOR_DIRS` + `FLOOR_FILES` + `STRICT_DIRS`) : **tout nœud texte littéral y est une faute**, sauf s’il n’a
aucun mot ordinaire (acronymes et codes : FSMA, eIDAS, 60 kB, BE • EUR), s’il ressemble à du code
(`Intl.DateTimeFormat`), ou si la ligne porte `// check-copy:ignore` (wordmark « KREDIT Admin », énumération
« Langue • Language • Taal • Sprache », fixtures de la démo d’adresses). L’oracle « est-ce de la copie ici ? »
n’est pas une liste de mots inventée : ce sont les **valeurs des dictionnaires `fr`** du projet.

Conséquences : le simulateur construit ses listes d’options à partir de `INCOME_TYPES` /
`EMPLOYMENT_STATUSES` / `LOAN_PURPOSES` **exportés par le moteur** et résout
`simulator.warning.<code>` / `documents.<code>` / `simulator.scoreFactor.<code>` via
`trOu(clé, repli)` ; les onglets produits n’ont plus leur dictionnaire parallèle en `label: { fr: … }` ; le
pied de page et l’en-tête sont intégralement traduits (`footer.*`, `nav.dashboard`, `shell.logout`), avec les
noms de produits repris aux clés `products.*` (le pied écrivait « Crédit Personnel », cinquième orthographe
du produit) ; les cartes de stats de la console sont identifiées par clé (`dashboard.stat.<clé>`) et non
plus par leur libellé français ; le risque KYC circule comme code (`LOW`/`MEDIUM`/`HIGH`) et n’est nommé
qu’au rendu.

Verrou : `tests/unit/simulator-footer-i18n.spec.tsx` — chaque code exporté par le moteur doit avoir sa clé
dans les quatre langues, la taille des listes doit suivre les unions TypeScript, et le rendu serveur du
simulateur comme du pied de page doit montrer la langue du segment (« Vaste betrekking », « Unbefristet »,
jamais « Sans emploi »).

## 9ter. Copie « hors React » : `<head>` et manifeste PWA

Deux surfaces ne voient **pas** le composant qui rend la page, et ont donc leur propre chemin de
traduction :

| Surface | Source de la copie | Contrôle |
|---------|--------------------|----------|
| `<title>`, meta `description`, `og:*`, `twitter:*` | `app/[locale]/layout.tsx` → `t(locale, "common:seo.title")` / `common:seo.description` | `generateMetadata` testé pour les 4 locales |
  Le layout enfant pose `title.absolute` (et non `title.default`) : le motif `%s | KREDIT` du layout
  racine aurait produit « KREDIT — Krediet & Beleggen (België) | KREDIT », un doublon de marque ; les
  titres de page futurs restent templatés.
| `manifest` (nom, description, `lang`, `start_url`, `shortcuts`, `protocol_handlers`, `share_target`) | `lib/pwa-manifest.ts` → `buildManifest(locale)`, servi par `/manifest/{locale}.json` | `tests/unit/i18n-metadata.spec.ts` |

Le layout **racine** ne doit rien porter de traduit : il ne reçoit pas `params`, donc une valeur y
étant écrite est servie aux quatre langues (c'était le cas de `title.default`, `description`,
`twitter.title/description` et `manifest: "/manifest.json"`, dont le fichier pointait `start_url`
sur `/fr` — un visiteur `nl` installait une PWA qui ouvrait `/fr`). Il ne garde que le motif
`title.template`, les icônes, `applicationName`, `formatDetection`, `category`.

**Pourquoi un test de parité des dictionnaires** : `t(locale, key)` qui ne trouve pas la clé
retombe **silencieusement** sur `fr` (un `console.warn` en navigateur seulement). La parité
`fr/en/nl/de` (clés, variables ICU, blocs `plural`) est donc vérifiée dans
`tests/unit/i18n-metadata.spec.ts`, avec un détecteur de « valeur laissée en français » — une seule
exception admise, l'endonyme `common:language.fr = Français`. Le namespace `fr-BE.json` est un
override propre à `fr` et n'entre pas dans la comparaison.

## 9bis. Tables de locale — un seul endroit (`lib/i18n.ts`)

| Table | Rôle | Consommateurs |
|-------|------|---------------|
| `localeToIntl` | locale applicative → tag Intl du marché BE (`fr` → `fr-BE`) | `lib/formatters.ts` (ré-export), `lib/utils.ts` |
| `localeLabels` | nom vernaculaire affiché par le sélecteur (`Nederlands`) | `components/layout/Header.tsx` |
| `localeTagLabel` | étiquette technique `FR-BE` — **dérivée** de `localeToIntl` | `components/layout/Header.tsx` |
| `openGraphLocale` | `og:locale` / `og:locale:alternate` (l'énumération Open Graph refuse `fr_BE`) | `app/[locale]/layout.tsx` |
| `whatsappLocale` | code `language` envoyé à Meta (miroir de `backend/.../whatsapp.channel.ts`) | `app/[locale]/admin/notifications/page.tsx` |

**Règle:** aucun composant ne choisit un tag Intl. `formatEUR`, `formatEUR2`, `formatCurrency`,
`formatDate`, etc. prennent la **locale applicative** (`fr|en|nl|de`) et la convertissent dans `lib/` ;
le paramètre est obligatoire — un défaut `= "fr-BE"` faisait rendre du français à 3 marchés sur 4,
sans erreur. Les garde-fous `locale-tag-literal`, `locale-arg-literal`, `locale-list-literal` et
`intl-tag-in-ui` (`npm run check:hydration`) bloquent les recopies dans `app/` et `components/`.

## 10. SEO & accessibilité

- `<html lang>` aligné sur le segment (voir règle 6 de `docs/hydration.md`), `hreflang` alternates,
  `sitemap.xml` avec 4 locales, `og:locale`.
- Métadonnées par langue produites par `app/[locale]/layout.tsx` (`generateMetadata`), **jamais** par
  le layout racine : celui-ci ne reçoit pas `params`, donc `canonical: "/fr"` y était partagé par les
  quatre langues (/en, /nl, /de déclaraient le français comme URL canonique) et `og:locale: fr_BE`
  est une valeur hors énumération, rejetée au scrape. D'où `openGraphLocale` (table, ci-dessus),
  `canonical: /{locale}`, `og:url` par locale, `og:locale:alternate` pour les trois autres.
- Le bloc `openGraph` est déclaré **entier** dans `app/[locale]/layout.tsx` : Next remplace ce bloc
  entre parent et enfant au lieu de le fusionner, donc le redéclarer à moitié faisait disparaître
  `og:image`, `og:site_name` et `og:type` (vérifié sur le HTML de prod). Les constantes partagées
  (origine, nom du site, image sociale) vivent dans `lib/seo.ts`, et l'origine n'est plus écrite
  nulle part ailleurs.
- Contrôle rapide: `curl -s localhost:3000/nl | grep -E 'canonical|og:locale|hreflang'` → canonique
  `https://kredit.be/nl`, `og:locale content="nl_BE"`, quatre `hreflang` + `x-default`.
- Dates dans `<time datetime="2026-09-09">` — c'est exactement ce que produit `<RelativeTime>`
  (`dateTime` = instant exact en ISO, `title` = date absolue lisible, texte = écart humanisé).
